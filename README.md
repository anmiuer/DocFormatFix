# DocFormatFix

docx 文档结构识别 + 排版格式自动校准工具；同时支持 Markdown 结构规范化。识别 Word 原生标题样式，也能对没有样式的文档依据字号、加粗、段首编号等特征推断标题层级；只调整排版与结构，不改动正文文字。

- 自用 + 开源，MIT License
- 项目地址：https://github.com/anmiuer/DocFormatFix
- CLI 与 Tkinter GUI 共用同一套核心逻辑
- 输入支持 `.docx`、`.md`、`.markdown`
- 每次任务强制自动备份，备份目录与输出目录均可自定义
- 内置 3 套模板，支持可视化自定义格式、粘贴自然语言格式要求自动识别，并可保存与管理模板
- 模板文件被外部修改或删除时，程序会自动检测并同步到模板下拉框与管理面板

## 环境与安装

要求 Python 3.9+，主要面向 Windows。开发与测试使用 Python 3.13。

### 推荐启动方式（无窗口）

直接在资源管理器中双击：

- `DocFormatFix.vbs`：推荐，完全无窗口、无黑框；
- `启动DocFormatFix.bat`：兼容入口，只短暂闪一下黑框，随后由 VBS 隐藏启动。

两者都会调用 `launcher.py`，以 `pythonw` 运行，**不会创建可操作终端**，因此无法通过终端执行命令；GUI 关闭后启动器进程自动退出。

启动器每次启动都会自动检查：

- Python 版本是否满足 3.9+；
- `tkinter`、`python-docx`、`tkinterdnd2` 是否可用；
- `gui.py`、`src`、`templates` 等项目文件是否完整；
- 备份/输出目录是否可写。

环境完整时直接打开 GUI。若缺失，会弹出环境检查窗口，可选择：

- 自动下载安装缺失的 pip 依赖；
- 选择本地 Python 环境（`python.exe` 或环境文件夹）；
- 选择本地离线安装文件（`.whl`、`.tar.gz`、`.zip`、`requirements.txt`）；
- 仅有可选依赖缺失时，也可以“仍然启动”。

启动日志在 `logs/launcher.log`；选择的本地环境会记录在 `config/launcher.json`，下次启动沿用。

### 手动安装与开发调试

```bash
pip install -r requirements.txt
python gui.py
```

`python gui.py` 会保留终端窗口，不经过启动器的环境自检，适合开发调试。默认依赖 `python-docx` 与 `tkinterdnd2`；Windows 原生拖放不依赖 `tkinterdnd2`，缺少时仍可使用原生拖放。

可选依赖：

```bash
# Docling 辅助校验插件（默认不启用）
pip install docling
```

## 快速开始

### GUI

推荐双击 `DocFormatFix.vbs` 启动；开发时也可以在终端运行：

```bash
python gui.py
```

界面主要区域：文件选择、模板与参数（含【格式设置…】【识别格式要求…】【管理模板…】）、格式识别与原文、段落明细、实时日志标签页、底部操作按钮。主区域默认展示原文视图，日志放在独立标签页中，避免占用原文高度。

推荐流程：

1. 选择【单个文件】或【整个文件夹批量处理】，选择路径；不支持的 doc/pdf/docm 等会以灰色行标出并记录原因。也可以把**多个 docx / md 文件或文件夹直接拖入窗口**，程序会作为批量任务载入并自动预扫描。
2. 选择模板。如需调整 Word 输出格式，点击【格式设置…】修改字体、字号、缩进等，或另存为新模板；如果已有现成的格式要求文本，点击【识别格式要求…】粘贴后自动识别；需要重命名、复制、删除或导入模板时，点击【管理模板…】；如需修改备份/输出位置，点击底部【目录设置…】。
3. 点击【预扫描文档】。该步骤只读文档，不会修改任何文件。
4. 在【格式识别与原文】页查看结果：
   - 左侧自动汇总文档中出现的格式（标题、正文、参考文献、表格、代码块、数学公式、列表、引用、图注、表注等），显示数量、置信度分布和一段原文示例
   - 单击某个格式，右侧原文中所有同类段落会整体高亮，便于快速判断识别是否准确
   - 右侧原文视图用不同底色区分格式，并标注段落序号与识别类型
   - 相邻同识别类型、间隔不超过 2 个空段落的文本块会默认合并为一个显示块；组首显示“· N段”，组内不插空行
   - 点击组首的格式标签可选中整组；点击具体行只选中该段；拖选一段或多段后点击【拆解所选】可将其拆成独立显示块
   - 需要恢复默认合并时，右键原文选择【恢复自动合并（全部）】
   - 空段落不在原文视图显示，仍完整保留在【段落明细】和输出文档中
   - 点击【专注原文】可隐藏左侧格式列表，让原文视图占满主区域；运行日志在独立标签页中查看
5. 在原文中选中内容后可手动修正识别结果：
   - 单击任意段落可选中整段；Ctrl+单击可加选或取消某段；Shift+单击可从上一段连续选到当前段；按住鼠标拖动可自由选择任意文字；选中内容以蓝色高亮
   - 原文只读，可选中和复制，但不能输入、删除或粘贴修改
   - 【合并所选】把跨段选中的多个段落合并为同一识别块（组N），统一按第一个段落的类型格式化
   - 【保护所选】把所选段落标记为“不格式化”，执行时保留原字体、字号、缩进等特殊格式
   - 【取消保护】恢复这些段落的自动格式化
   - 【改判为】把所选段落改判为一级/二级/三级标题、正文、参考文献、图注、表注等
   - 右键原文也可执行相同操作；选择部分文字时，操作作用于文字所在的整段
6. 在【段落明细】页逐段核对：
   - 绿色：高置信，执行时会自动修改
   - 黄色：中置信，仅标记，不修改
   - 红色：低置信，仅记录，跳过
   - 灰色：手动保护或公式自动保护，不参与格式化
   - 右键任意段落行，可改判或恢复自动识别
7. 确认后点击【执行格式化】。程序先强制备份，再输出到指定输出目录，并生成 TXT 报告；勾选后会同时生成 HTML 报告。Markdown 文件输出规范化后的 `.md`。
8. 可通过底部按钮打开输出/备份目录，或使用【恢复备份】还原原始文档。

### CLI

```bash
# 批量处理文件夹（docx / md 混合也可以）
python main.py --dir ./tests/test_docs --template competition_report

# 处理单个 Word 文件并生成 HTML 报告
python main.py --file ./论文.docx --template undergraduate_thesis --html

# 处理 Markdown 文件（结构规范化，不使用 Word 字体模板）
python main.py --file ./笔记.md --html

# 自定义备份与输出目录
python main.py --dir ./docs --backup-dir D:\backup\docformatfix --output-dir D:\output\docformatfix

# 关闭标题推断，只使用 Word 原生标题样式
python main.py --dir ./docs --template common_homework --no-infer

# 启用附加清理
python main.py --dir ./docs --cleanup merge_empty revisions spaces

# 查看历史备份 / 恢复最近一次
python main.py --list-backups
python main.py --restore latest
```

CLI 没有预览与人工覆写能力，只使用自动识别结果；段落合并、保护与手动改判仅在 GUI 中提供。Markdown 使用结构规范化，Word 模板只对 `.docx` 生效。

## 目录设置与拖拽

- GUI 底部【目录设置…】可修改备份目录和输出目录，支持绝对路径或相对项目目录的路径
- 保存后写入 `config/settings.json`，下次启动自动沿用
- CLI 通过 `--backup-dir` / `--output-dir` 临时覆盖配置
- 支持把文件或文件夹直接拖入窗口任意位置；一次拖入多个文件会作为批量任务处理
- 拖入后自动预扫描；不支持的格式会以灰色行标出
- Windows 下会同时启用两套拖放后端：
  - 内置 `WM_DROPFILES` 原生拖放，挂接主窗口与全部子控件；
  - tkinterdnd2 的 OLE 拖放，递归注册全部控件。
- 两套后端同时生效，重复事件会自动去重；拖到文件列表、原文、Notebook、按钮等任意位置都能接收
- 启动日志会显示“拖拽后端：native+tkinterdnd2”、注册窗口/控件数量，或具体失败原因
- 每次成功收到拖入都会记录“收到拖入 N 个路径”，便于排查

### 拖拽无反应时的排查

1. 先看【实时日志】中的“拖拽后端”：
   - 正常应为 `native+tkinterdnd2`；
   - 若没有 tkinterdnd2，日志会给出当前 Python 的安装命令，例如：
     `C:\...\python.exe -m pip install tkinterdnd2`
2. 不要使用 `runas /trustlevel:0x20000` 启动。受限启动方式可能让资源管理器无法把拖放数据送入程序，即使窗口和日志看起来正常。
3. 如果当前终端是管理员权限，Windows 也会阻止普通权限的资源管理器拖放；请改用普通权限启动。
4. 最省事的方式：直接在资源管理器中双击项目根目录的 `DocFormatFix.vbs`。它以无窗口方式启动，继承资源管理器的普通权限，拖放最稳定；`启动DocFormatFix.bat` 只是兼容入口，会短暂闪一下黑框。
5. 如果日志完全没有“收到拖入”，说明系统没有把拖放事件送到程序；请把“拖拽后端”附近和拖放后的日志发来继续定位。
6. 如果日志有“收到拖入”但文件列表没变化，把其后的“发现文件/预扫描”日志发来。

## 格式识别与自定义格式

### 识别结果面板

预扫描完成后，左侧会按文档实际出现的格式自动生成汇总列表：

- 一级标题、二级标题、三级标题、正文、参考文献、表格、代码块、数学公式、公式、列表、引用、图注、表注、分隔线
- 每种格式显示数量/段数、置信度分布（高/中/低）和一段原文示例
- 单击某个格式后，右侧“文档原文”中所有该格式段落会整体高亮，便于快速检查识别是否准确
- 原文视图按格式使用不同底色，并标注段落序号与识别类型；空段落显示为“（空段落）”
- 原文内容保持原样，仅附加类型标注与序号，不会因预览而修改文档

“段落明细”页保留逐段置信度、来源与判定依据，并支持右键手动改判。两类视图使用同一份识别结果，改判后会同步刷新。

### 格式设置

点击模板旁的【格式设置…】可打开格式编辑器：

- 左侧选择段落格式，可设置：字体、字号、加粗、首行缩进（按字符）、行距（倍数或固定磅值）、段前、段后、对齐
- 支持一级/二级/三级标题、正文、参考文献、表格、图注、表注；表格设置只统一表格内文字，不改变表格结构
- 右侧提供字体效果预览
- 【应用当前格式】只影响本次任务，不会改动原始文档
- 【载入内置默认】把当前格式恢复为内置默认值，点击应用后生效
- 【另存为模板…】把整套格式保存为 `templates/<名称>.json`，并自动切换为当前模板，下次启动仍可使用
- 切换模板下拉框会重新读取对应 JSON；自定义但未另存的修改仅在当前会话生效
- Markdown 文档使用结构规范化，点击【格式设置…】会提示字体模板不适用

“参考文献”格式用于“参考文献”标题之后的文献条目；标题本身仍按一级标题处理。

### 智能识别格式要求

主界面“2. 模板与参数”中的【识别格式要求…】会在点击后打开专用输入框，不占用主界面空间。

- 支持“一级标题：黑体，三号，加粗，段前12磅，段后12磅，1.5倍行距”这类“标签：规格”写法
- 也支持逐行规格、制表符/竖线表格、同一行写多个标签，以及“正文用宋体小四”这类表述
- 可识别：字体、中文字号（三号/小四等）与磅值、加粗/不加粗、居中/左/右/两端对齐、首行缩进（按字符）、行距（1.5 倍、单倍、双倍、固定值 20 磅）、段前/段后（磅或行）
- 未标注段落类型的规格按“正文”处理；页边距、页眉页脚、页码、分栏、字符间距等暂不支持，会在提示区逐条列出
- 识别结果以当前模板为基础合并：只覆盖识别到的字段，未识别字段保留原值
- 【应用到当前模板（本次任务）】只影响本次执行；【保存为模板…】写入 `templates/<名称>.json` 并切换为当前模板
- 识别完全基于本地规则，不需要联网或大模型

### 模板管理

点击【管理模板…】打开模板管理面板：

- 列表显示模板文件名、内置/自定义类型与可用状态；双击或【选用】切换当前模板
- 自定义模板支持重命名、复制、删除；内置模板只允许复制，避免误改内置模板
- 支持从外部 JSON 导入模板，也可直接打开 `templates` 目录
- 至少保留一个模板；删除前二次确认
- 手动修改模板 JSON、用外部编辑器保存，或直接新增/删除模板文件后，管理面板与主界面下拉框会在约 1.5 秒内自动同步
- 若当前模板有未另存的自定义格式，外部修改不会覆盖当前会话数据；外部删除时保留内存中的格式并在状态栏提示
- 手动修改 `config/settings.json` 后，置信阈值、HTML 报告、清理选项、备份/输出目录与默认模板也会同步到界面

## 手动合并与保护

原文视图支持两种选择方式，操作入口在视图上方工具栏，也可右键原文：

- **选择方式**：单击段落选中整段；Ctrl+单击加选/取消某段；Shift+单击从上一段连续选到当前段；按住鼠标拖动可自由选择任意文字。蓝色选区在点击工具栏按钮后仍保持可见。段间使用空行分隔，每段左侧有格式色条，段落边界清晰。
- **合并识别块**：拖选两个及以上段落后点击【合并所选】。多段会归入同一个“组N”，共享第一个段落的识别类型；例如被拆成两段的标题、跨行的作者信息可以统一按标题格式处理。此操作只统一识别类型与格式，不会物理合并 Word 段落或改动文字。
- **保护不格式化**：拖选段落后点击【保护所选】。被保护段落在执行时完全跳过格式校准，保留原有字体、字号、颜色、缩进等特殊格式，适合标题、作者名、手写签名说明等需要保持原样的内容。保护段落会以灰色显示，并汇总到左侧“保护”行。
- **取消保护 / 恢复自动**：可撤销保护或清除该段的手动标签与合并分组，重新使用自动识别结果。

选择部分句子时，操作会作用于该文字所在的整段。合并与保护会随文件、随段落索引保存，并在预扫描和最终执行时一并传入识别引擎；报告中的“来源”列会显示“手动·组N”或“保护”。

### 默认合并显示与手动拆解

- 原文视图会自动把**相邻、识别类型相同、间隔不超过 2 个空段落**的文本块合并成一个显示块；手动合并组不受空段落间隔限制
- 合并块只在视觉上合并，不修改 Word 段落、文字或模板格式；组首显示“· N段”，后续行用 `↳` 标记
- 点击组首的格式标签会选中整组；点击组内具体行只选中该段
- 用鼠标涂抹选中一段或多段后点击【拆解所选】，被选中的段落会成为独立显示块，前后段落也相应分开
- 右键原文或段落明细可选择【恢复自动合并（全部）】
- 拆解以原始段落为单位，不会把同一段文字拆成两个 Word 段落
- 空段落只显示在【段落明细】中，不占用原文视图

## Markdown、表格与公式

### Markdown

- 支持 `.md` 与 `.markdown`，可单文件、文件夹或一次拖入多个文件
- 规范化标题标记（ATX 空格、Setext 标题转 ATX）与块间空行
- 表格、代码围栏、数学公式块、YAML 元数据、列表与引用保持原内容和原结构；段落内硬换行（行尾双空格）不会被删除
- 输出文件为 `<原文件名>_formatted.md`
- 手动【保护所选】可让某个 Markdown 块完全不参与规范化
- 手动改判标题/正文会调整对应标题标记；表格/代码/公式等特殊块不会被强行改判
- Markdown 不套用 Word 的字体、字号、缩进模板

### Word 表格

- 表格的行列、合并单元格、嵌套表格与边框结构保持不变
- 表格单元格内的文字按模板中的“表格”格式统一字体、字号、加粗与行距
- 含数学公式的单元格段落自动跳过
- 表格内文字格式变化可能轻微影响行高，但不会改变表格结构

### 数学公式

- Word OMML 公式段落会自动识别为“公式”并保护，公式与公式段落格式保持不变
- 表格内的公式段落同样跳过
- Markdown 中的 `$...$` 与 `$$...$$` 公式原样保留
- 本工具只保护公式，不做 LaTeX/OMML 转换或公式排版重排

## 识别规则

### 预扫描

`src/pre_scanner.py` 只读遍历全部段落，采集字号、加粗状态、首行缩进、文本、对齐与样式信息。

- 字号直方图按字符数加权，出现最多的字号判定为正文基准字号
- 记录高于正文基准字号的候选标题字号
- 检测 Word 原生标题样式与大纲级别
- 统计表格、文本框数量并写入警告

### 判定顺序

1. GUI 手动标签（优先级最高）
2. 空段落
3. Word 原生标题样式 / 大纲级别（置信度 100）
4. 图注 / 表注（段首为“图/表 + 编号”，且不以句末标点结尾）
5. 首行缩进 > 1 磅：直接判定正文（置信度 95）
6. 启用推断时进行多特征打分
7. 未启用推断时，其余段落统一按正文处理
8. 参考文献章节后处理（见下）

### 标题打分

| 特征 | 分值 |
| --- | --- |
| 基础分 | +20 |
| 字号大于正文基准字号 | +30 |
| 加粗 | +20 |
| 短句（≤30 字）且无句末标点 | +15 |
| 段首编号匹配 | +30 |
| 常见章节关键词（摘要、目录、参考文献、致谢、附录、绪论、引言、结论等） | +25 |
| 段落长度 > 40 字 | -20 |
| 段落长度 > 80 字 | 再 -20 |
| 句末标点（。！？；…） | -25 |

分数限制在 0~100。达到 60 分才进入标题候选；编号模式决定候选层级，无编号时按候选标题字号从大到小映射为一级、二级、三级；关键词标题默认一级。

`1.` 这类简单阿拉伯数字编号会按文档上下文自适应：文档中同时存在 `一、` 与 `（一）` 时按三级标题；仅有 `一、` 时按二级标题；独立使用时按一级标题。`1.1`、`1.1.1` 始终按点号层级映射为二级、三级。

### 参考文献章节

文档中出现独立的“参考文献”/“References”标题后，后续段落会自动标记为“参考文献”：

- 一直标记到下一个非文献条目的标题，或“致谢、附录、作者简介、声明、结论”等结束章节
- 以 `[1]`、`（1）`、`1.` 等开头的文献条目不会被误判为章节结束
- “参考文献”标题本身仍是一级标题，文献条目使用“参考文献”格式
- 该规则基于章节位置推断，仍建议在原文视图中点击“参考文献”格式复核高亮范围

### 置信度与修改策略

- `score >= 阈值`：高置信，自动应用模板格式
- `60 <= score < 阈值`：中置信，只标记，不修改
- `score < 60`：低置信，记录并跳过
- 正文的置信度单独计算：首行缩进 95；长段落或句末标点 90；短行且存在弱标题证据 55；普通短行 75

默认阈值 70，可在 GUI 高级选项的 60~90 滑块中调整，或用 CLI 的 `--threshold` 指定。

## 模板

模板位于 `templates/`，内置：

| 文件 | 场景 |
| --- | --- |
| `undergraduate_thesis.json` | 本科毕业论文 |
| `competition_report.json` | 竞赛申报书 |
| `common_homework.json` | 课程作业 |

每套模板都包含一级/二级/三级标题、正文、参考文献、表格、图注、表注。Markdown 文件只使用结构规范化，不使用这些字体模板。

字段说明：

```json
{
  "一级标题": {
    "font": "黑体",
    "size": 16,
    "bold": true,
    "indent": false,
    "line_spacing": 1.5,
    "space_before": 12,
    "space_after": 12
  },
  "正文": {
    "font": "宋体",
    "size": 12,
    "bold": false,
    "indent": true,
    "line_spacing": 1.5
  },
  "参考文献": {
    "font": "宋体",
    "size": 10.5,
    "bold": false,
    "indent": false,
    "line_spacing": 1.25
  },
  "表格": {
    "font": "宋体",
    "size": 10.5,
    "bold": false,
    "line_spacing": 1.25,
    "space_before": 0,
    "space_after": 0
  },
  "图注": {
    "font": "宋体",
    "size": 10.5,
    "bold": false,
    "align": "center"
  }
}
```

- `indent: true` 表示首行缩进 2 字符（按该段字号计算）；也可写成数字，如 `1.5` 表示缩进 1.5 字符，`0` 表示不缩进
- `line_spacing` 可写倍数（`1.5`），也可写固定磅值字符串（如 `"20pt"` 或 `"20磅"`）
- `align` 可取 `left`、`center`、`right`、`justify`
- `表格` 只作用于单元格文字，不会改变行列、合并单元格或边框
- 可自行新增 JSON 文件，GUI 下拉框与 CLI `--template` 会自动发现
- 也可以直接在 GUI【格式设置…】中修改并另存为新模板
- 模板缺少某类段落规则时，回落使用“正文”规则；缺少“表格”规则时表格文字保持不变

## 附加清理

三个选项默认关闭，按需勾选：

1. **清理连续空段落**：连续多个空段落只保留一个；包含分页符、图片、对象、域代码的“空段落”不会被删除。
2. **删除修订痕迹、隐藏文字**：展开插入修订、删除删除修订、移除隐藏文字 run。
3. **清除多余半角/全角空格**：全角空格转为半角，连续空格压缩为一个，去除段首/段尾多余空格。

清理只涉及空白字符与修订结构，不改变正文语义。

## 备份、输出与报告

- 目录来源：`config/settings.json` 中的 `backup_dir` / `output_dir`，GUI【目录设置…】可修改并持久保存
- 备份：`<备份目录>/<YYYYMMDD_HHMM>/`，保留源目录相对结构，并写入 `manifest.json`（记录原始绝对路径）
- 输出：Word 为 `<输出目录>/<相对路径>/<文件名>_formatted.docx`，Markdown 为 `<文件名>_formatted.md`
- 报告：`<输出目录>/reports/docformatfix_<时间戳>.txt`，勾选 HTML 时同时生成 `.html`

备份是强制动作，无法在 GUI 中关闭；备份失败时整个任务中止，不会继续改文档。

恢复：
- GUI 底部【恢复备份】选择任务后一键还原
- CLI `python main.py --restore latest` 或指定备份目录
- 恢复依赖 `manifest.json`；缺失清单的旧备份只能查看文件，无法自动定位原路径

## 约束与边界

- 仅处理 `.docx`、`.md`、`.markdown`；`.doc`、`.docm`、`.pdf`、`.wps` 等会跳过并记录原因
- Word 只处理主体段落与表格单元格文字；文本框、艺术字、图片内文字不处理，扫描阶段会给出警告
- Word 表格保留行列与合并结构，但较大的字体/行距调整可能轻微改变表格行高
- Word 数学公式段落自动保护，不修改公式；不做 LaTeX/OMML 转换或公式重排
- Markdown 只做结构规范化，不套用 Word 字体模板；复杂 HTML、自定义扩展语法按原内容保留
- Word 自动编号不写入段落文本，无法作为编号特征；这类文档请依赖原生标题样式或手动覆写
- 标题推断存在误判风险，GUI 的预扫描预览是主要复核手段；建议不要跳过预扫描直接批量执行
- 参考文献章节依赖标题文本与章节边界推断，长文档或特殊排版仍需人工确认高亮范围
- 中/低置信段落不会修改，宁可少改也不误改
- 程序只校准格式，不校验文字内容、错别字或逻辑
- 首次使用建议先复制一份文档试运行；虽然每次都会强制备份，仍不建议直接处理唯一原件
- 模板中的字体需系统已安装（Windows 下宋体、黑体默认可用；Linux 需自行配置中文字体）
